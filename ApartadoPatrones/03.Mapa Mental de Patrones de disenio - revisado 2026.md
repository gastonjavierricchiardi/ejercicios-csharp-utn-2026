## 🎯 **Idea central:** _Patrones de Diseño_

| Categoría | Patrón (asociación rápida) | Palabra o idea del enunciado |
| --- | --- | --- |
| **Creacionales — crear objetos** | **Singleton** (único) | Una única instancia / punto de acceso global. |
| | **Factory Method** (fábrica delegada) | Las subclases del creador deciden qué producto concreto crear. |
| | **Abstract Factory** (fábrica de familias) | Familias de productos relacionados y compatibles. |
| | **Builder** (construcción por etapas) | Objeto complejo / construcción paso a paso / distintas configuraciones. |
| **Estructurales — organizar o relacionar objetos** | **Adapter** (adaptador / traductor) | Interfaces incompatibles / integración de código existente o legado. |
| | **Composite** (compuesto / árbol) | Estructura parte–todo / hojas y compuestos tratados uniformemente. |
| | **Decorator** (decorador por capas) | Agregar funcionalidad envolviendo un objeto y manteniendo su interfaz. |
| | **Facade** (fachada simplificada) | Ocultar la complejidad de un subsistema mediante un acceso sencillo. |
| **De comportamiento — comunicación y responsabilidades** | **Strategy** (estrategia intercambiable) | Cambiar el algoritmo o comportamiento mediante una estrategia. |
| | **Observer** (observador / suscriptor) | Un objeto avisa a varios observadores de un cambio o evento. |
| | **Chain of Responsibility** (cadena de responsables) | Una solicitud pasa por manejadores; cada uno evalúa si actuar y/o continuar la cadena. |
| | **Template Method** (método plantilla) | Estructura y orden generales fijos; algunos pasos varían en las subclases. |

> **Para parcial:** las palabras clave son pistas, **no pruebas suficientes**. Primero identificar qué problema resuelve el patrón.

# 3 ramas principales, cada una con 4 patrones

## 🌱 **1. CREACIÓN (cómo se crean objetos)**

**Idea clave:** _«Cómo nace el objeto»_

- **Singleton → «Único»**: una sola instancia.
- **Factory Method → «Fábrica delegada»**: la subclase creadora decide el producto concreto.
- **Abstract Factory → «Fábrica de familias»**: crea productos relacionados y compatibles.
- **Builder → «Construcción por etapas»**: construye un objeto complejo paso a paso.

---

## 🧩 **2. ESTRUCTURA (cómo se organizan o combinan objetos)**

**Idea clave:** _«Cómo se conectan o envuelven»_

- **Adapter → «Adaptador / traductor»**: hace compatibles interfaces distintas.
- **Composite → «Árbol parte–todo»**: reúne hojas y compuestos.
- **Decorator → «Capas de responsabilidades»**: agrega funcionalidad envolviendo objetos.
- **Facade → «Fachada simple»**: simplifica el acceso a un subsistema.

---

## 🔄 **3. COMPORTAMIENTO (cómo se comunican o varían)**

**Idea clave:** _«Cómo se comportan o colaboran»_

- **Strategy → «Estrategia intercambiable»**: cambia el algoritmo.
- **Observer → «Suscriptores / notificaciones»**: avisa cambios o eventos.
- **Chain of Responsibility → «Cadena de manejadores»**: deriva una solicitud entre responsables, que pueden intervenir.
- **Template Method → «Plantilla con orden fijo»**: mantiene el proceso general y permite variar pasos.
