# Breve análisis:

### 1. Ventajas de pasar un único `Visitante`

En lugar de pasar varios datos sueltos:

```csharp
ControlarDocumento(nombre, apellido, dni)
```

pasamos un solo objeto:

```csharp
ControlarDocumento(Visitante visitante)
```

Ventajas:

- menos parámetros;
- los datos permanecen agrupados en el objeto al que pertenecen;
- si mañana `Visitante` incorpora otro dato necesario, no necesariamente hay que cambiar la firma;
- el código expresa mejor la intención: el guardia controla **un visitante**, no tres valores aislados.

Además, UML lo representa como una relación de **uso/dependencia**, porque `Guardia` recibe temporalmente un `Visitante` como parámetro.

### 2. Desventaja principal

`Guardia` ahora queda acoplado a `Visitante`:

```csharp
public string ControlarDocumento(Visitante visitante)
```

Eso significa que el método espera específicamente ese tipo. Antes:

```csharp
ControlarDocumento(int dni)
```

solo dependía de un `int`.

Entonces:

```text
Pasar datos sueltos
→ menos dependencia entre clases
→ más parámetros

Pasar Visitante
→ menos parámetros
→ más dependencia entre Guardia y Visitante
```

### 3. Para este ejercicio

La opción con un único `Visitante` me parece la más interesante porque **es exactamente lo que la consigna quiere que analicemos**:

```csharp
public string ControlarDocumento(Visitante visitante)
{
    return $"Adelante {visitante.Presentarse()} con dni {visitante.GetDni()}";
}
```

Y ahora ya aparece una nueva idea respecto de EJ10: **los objetos empiezan a colaborar entre sí**. `Guardia` le pide información a `Visitante` mediante sus métodos públicos.
